# IT Procurement in a Software Project

Real-Time Scenario:
IT Procurement in a Software Project

Scenario Background

A bank wants to develop a new Mobile Banking Application to improve customer experience. The bank's internal IT team cannot handle the full workload, so they decide to procure external IT services.

## 1. Plan Procurement Management (Real Situation)

The Project Manager identifies what must be outsourced:

•    Mobile app development (Android & iOS)
•    Cybersecurity testing
•    Cloud hosting infrastructure
•    UI/UX design

Internal approval is taken, budget is allocated, and procurement strategy is planned.

## 2. Conduct Procurements (Real Situation)

Step 1: RFI (Request for Information)

The bank sends RFI to several IT vendors asking:

•    What technology stack do you use?
•    Experience in banking apps?
•    Security certifications?

Purpose: Understand available solutions, not pricing.

Step 2: RFP (Request for Proposal)

After analyzing RFIs, the bank sends RFP to shortlisted vendors:

•    Detailed project scope
•    Expected timeline
•    Required security standards
•    Support & maintenance

Vendors submit technical + financial proposals.

Step 3: Vendor Selection

The bank evaluates vendors based on:

•    Cost
•    Past banking projects
•    Security compliance
•    Delivery timeline

Vendor ABC Technologies is selected.

## 3. Contract Types Used (Real-Time Examples)

A. Fixed-Price Contract (Core App Development)

Used for: Mobile App Development
Why: Scope is clearly defined.
Example:

•    ABC Technologies will develop the complete mobile app for $200,000 in 8 months.
•    Any cost overrun is vendor’s responsibility.

👉 This is a Firm Fixed Price (FFP) contract.

B. Fixed Price Incentive Fee (FPIF)

Used for: Early delivery
Example:

•    If the vendor delivers the app 1 month early, they get $15,000 bonus.
•    Encourages timely completion.

C. Cost Reimbursable Contract (Cybersecurity R&D)

Used for: Penetration testing & security research
Why: Scope is uncertain due to evolving threats.
Example:

•    Bank pays actual testing cost + $30,000 fixed fee.
•    This is a Cost Plus Fixed Fee (CPFF) contract.

Risk lies mostly with the bank.

D. Time & Materials Contract (Support & Maintenance)

Used for: Post-launch support (bug fixing, minor updates)
Example:

•    Developer rate: $50/hour
•    Cloud engineer: $70/hour
•    Bank pays based on actual hours worked.

Suitable because effort varies month to month.

E. Purchase Order (PO)

Used for: Cloud Services
Example:

•    Purchase Order for Amazon Web Services (AWS) cloud storage – $10,000/month
•    Commodity-based procurement.

## 4. Control Procurements (Real Situation)

•    App milestones are reviewed monthly
•    Code quality audits are conducted
•    Invoices are matched with:
o    Purchase Order
o    Delivery reports
o    Invoice (Three-way matching)

Any deviation is handled through change requests.

## 5. Close Procurements (Real Situation)

Once:

•    App is live
•    Security standards met
•    All payments cleared

The Project Manager:

•    Signs contract closure documents
•    Releases final payment
•    Archives procurement records

Procurement is officially closed.

## One-Line Exam Summary

A real-time IT procurement scenario involves outsourcing software development using Fixed Price contracts for defined scope, Cost Reimbursable for uncertain work, Time & Material for support, and Purchase Orders for commodities, following procurement lifecycle steps from planning to closure.
