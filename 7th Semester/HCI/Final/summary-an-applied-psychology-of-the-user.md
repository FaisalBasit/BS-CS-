# An Applied Psychology of the User
An Applied Psychology of the User

Summary:

The applied psychology assures reliably user-computer interaction. The psychology of an individual user centers on the cognitive abilities (eg. Learning, performing and reasoning) of the user and these cognitive aspects plays a vital role in making scientific progress.

The role of the user could not be overlooked in the success or failure of any system. Therefore, there is a need to study the users objectively so that the systems could suit the users’. One should not only pay attention to the technical factors but also take into account the users’ point of view and ease.

The users’ are interested in achieving their goals with minimum effort, via certain task structures provided to them by using their own knowledge and processing limits. This logical behavior could be expressed as:

Users’ behavior = Users’ goals + Task structure + Users’ knowledge & Users’ processing limits

Therefore, to know users’ behavior the first step is to understand users’ goals, that is, making an understanding of users’ objectives that they would like to accomplish. After that there is a need to know the steps that users’ would ‘like’ or ‘not like’ to perform, i.e., to develop an understanding of the tasks structure. One of the most important parts of the task structure is user interface. The final step is to understand users’ knowledge about the existing task structure and the mental processing limits of the users’. The two main traits of the humans’ processing limits are: restricted short term memory and propensity to make errors irregularly. These human processing limits could be overcome by breaking the larger tasks into smaller which not only lays lesser load on memory but also bounds the scope of errors.

In order to control the users’ behavior, one of the above mentioned determinants of the users’ behavior could be changed so that the users’ performance can be enhanced. For example:

The task structure could be altered by making improvements in the user interface.
The users’ knowledge could be increased by teaching users’ more efficient methods.
The users’ inclination to make errors could be controlled by efficient error recovery.
The set of users’ goals defined by users’ themselves could be organized by automating few tasks that could be performed interactively.
The users’ behavior is an important aspect of human-machine interaction. To gauge the behavior is complex and is not easy. There are various extents to which the behavior could be studied and certain trade-offs to be made between these dimensions. Therefore, there is a need set the priorities regarding the dimensions of the behavior. For example, speed could be sacrificed for ease of learning. Given below are the dimensions of the behavior:

Functionality: A series of tasks to be performed by the users’.
Learning: The time taken by the user to learn given set of tasks.
Time: The time taken by the user to perform given set of tasks.
Errors: The total number of errors encountered while performing the tasks and severity of these errors is also important.

Quality: The excellence of the output being received by performing the tasks.
Robustness: The degree of comfort in performing new and unexpected tasks.
Acceptability: Overall subjective feeling of the system perceived by the users’.
The users’ could be distinguished by their knowledge and particular task structure.

User knowledge is somewhat correlated with the experience, therefore, on this basis the users’ could be classified as: novice – is in initial stage of learning and using the system and expert – mastered in some portion of the system. There is a certain variation in the behaviors of a novice and expert users’. The novice users’ are engaged in problem solving activity that is, to them everything is a problem. The expert users are familiar with the system and for them using a system becomes a routine cognitive skill. Therefore, the significance of the dimensions of behavior depends on the type of the users’. For novice, learning and performing the task is of primary importance and they are least concerned with the time taken to perform the tasks. On the other hand, the expert users are more interested in performing their tasks speedily and accurately. Moreover, the novice users are more prone to request structure variations whereas expert users are quite immune.

The user interface is the primary mean of interaction between the users and computers.

As per the designer’s point of view the user interface is a terminal comprises of hardware and software that collects, interprets and displays data to the users. This definition might be satisfactory from designers’ point of view but it does not reflect users’ perspective. Psychologically, “the user interface is any part of the computer system that the user comes in contact with – either physically, perceptually or conceptually.”

The users’ create a “conceptual view” of the system from the entire behavior of the system. Thus this conceptual view of the users plays integral part in designing the user interface.

The conceptual model is the information that classifies the overall working of the system and its use in accomplishing the tasks. Therefore, the conceptual model must derive from the overall behavior of the system and users must be aware of the conceptual model being followed. Thus, the user interface is not only the thing to be used at the terminals but also includes the training and documentation.

The user interface is not just happen thing and it is more than the add-on component; it influence overall use of the computer system.

The moral is that the user interface is more than an add-on component; it penetrates deep into the computer system. The user interface must be considered early in the design process if it is to be really designed and not just happen.

There is a need of an experimental process for user interface design where experimentation is treated as a feedback for designing the user interfaces. Furthermore, the results of analyzing users’ behavior might not be attractive, therefore, for gradual improvements in the relationship between users and computer systems there is a need to analyze the users’ behavior as an iterative cycle
